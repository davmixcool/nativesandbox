## Install

```bash
npm install nativesandbox
```

Node 22 or newer. Zero runtime dependencies — nativesandbox talks to the container engine over
its own socket and bundles nothing.

## Check the host first

The most common failure is not a bug in your code: it is an engine that is not reachable. Ask
before you depend on it.

```ts
import { Sandboxes } from "nativesandbox";

const sandboxes = new Sandboxes();
const health = await sandboxes.check();

if (!health.ok) {
  throw new Error(`No container engine: ${health.problem}`);
}
console.log(`engine ${health.engine}`);
```

`check()` never throws. It answers `{ ok, engine }` or `{ ok, problem }`, which makes it safe to
call at startup — the alternative is discovering the problem on a user's first command. If the
engine is missing, [requirements](/getting-started/requirements) covers installing it.

## Create a sandbox

```ts
import { Sandboxes, MiB } from "nativesandbox";

const sandboxes = new Sandboxes({ root: "/var/tmp/sandboxes" });

const box = await sandboxes.create("job-1", {
  runtime: "node",
  memory: MiB(512),
  cpus: 1,
});
```

The name is yours to choose and is how you find the sandbox again. Calling `create()` with the
same name returns the same sandbox as long as its shape still serves the request — see
[sandboxes](/guides/sandboxes).

<Note>
  `memory` is a branded type, so `memory: 512` will not compile. Write the unit — `MiB(512)`,
  `GiB(2)` — and the ambiguity between megabytes, mebibytes and bytes cannot reach the engine.
</Note>

## Run a command

```ts
const result = await box.exec("node --version");

result.code;        // 0
result.stdout;      // "v22.11.0\n"
result.stderr;      // ""
result.timedOut;    // false
```

Commands run through a shell in `/workspace`, so pipes, redirects and `&&` all work:

```ts
await box.exec("npm install --silent && npm test", { timeoutMs: 120_000 });
```

`exec` resolves rather than throwing on a non-zero exit — a failing build is a result, not an
exception. See [running commands](/guides/commands) for streaming, timeouts and cancellation.

## Move files in and out

```ts
await box.writeFile("/src/main.js", "console.log(41 + 1)");

const { stdout } = await box.exec("node src/main.js");   // "42\n"

const built = await box.readFile("/dist/bundle.js");     // Buffer
box.exists("/dist/bundle.js");                           // true
```

These are host reads and writes, because the workspace is a bind mount rather than a channel to
a guest. `box.workspaceDir` is the directory on the host, and reading it is reading the sandbox.

## Clean up

```ts
await box.stop();               // keeps the workspace; the next create() starts it again
await sandboxes.remove("job-1"); // removes the container AND the workspace
sandboxes.close();               // stops the housekeeping timer
```

Call `sandboxes.close()` when your process is shutting down. The timer is unref'd, so it will
never keep a process alive on its own, but stopping it is tidier than leaving it to the runtime.

## All together

```ts
import { Sandboxes, GiB, SandboxError } from "nativesandbox";

const sandboxes = new Sandboxes({ root: "/var/tmp/sandboxes" });

try {
  const box = await sandboxes.create("build", { memory: GiB(1), cpus: 2 });
  await box.writeFile("/package.json", JSON.stringify({ name: "x", version: "1.0.0" }));

  const install = await box.exec("npm install --silent", { timeoutMs: 180_000 });
  if (install.code !== 0) throw new Error(install.stderr);

  console.log(await box.readFile("/package-lock.json"));
} catch (error) {
  if (error instanceof SandboxError && error.code === "unavailable") {
    console.error("the engine went away mid-run");
  }
  throw error;
} finally {
  await sandboxes.remove("build");
  sandboxes.close();
}
```
